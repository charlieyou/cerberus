**Index derivation.** `printf '%d\n' "0x$(echo -n "$ARTIFACT_ID:$REVIEWER" | _sha256_hex | head -c 8)"` mod 3. Use Bash arithmetic; first-8-hex-digits as a 32-bit unsigned integer always fits in Bash 64-bit signed math.

**Determinism scope (D12).** `<artifact_id>` is `realpath`, so determinism is per-machine and per-checkout-location. Two engineers reviewing the same logical artifact at different absolute paths get different strategy assignments — accepted v1 behavior; cross-machine fixture-test replay goes through `--debate-seed N` (which seeds peer ordering), not the strategy hash.

**Wiring map** (strategy assignment propagation):
- `<artifact_id>` per review type → `compute_artifact_id` → SHA-256 → first 8 hex → mod 3 → strategy index → strategy file path → exported `STRATEGY_DIRECTIVE_PATH_<reviewer>` → bin/review-gate substitution slot in reviewer prompt

### Implementation Notes

**Why iterative substitution.** The canonical pattern's negated character classes consume one boundary character on each side. A single-pass `sed -E` on `Claude Codex` redacts only `Claude`: the first match consumes the shared space as its trailing boundary, leaving `Codex` with no preceding boundary for a second match in the same pass. Iterating until the buffer is idempotent fixes this without resorting to BSD-only `:a; ...; ta` label form.

**Word-boundary form.** The canonical `(^|[^A-Za-z0-9_])<term>($|[^A-Za-z0-9_])` form is the only word-boundary spelling accepted by both BSD and GNU grep under POSIX ERE. BSD-only `[[:<:]]`/`[[:>:]]` and GNU-only `\<`/`\>`/`\b` are forbidden — either would silently fail on the other platform before any anonymization runs.

**Capture-group numbering.** With the alternation `(^|[^A-Za-z0-9_])(<term1>|<term2>|...)($|[^A-Za-z0-9_])`, the trailing boundary is `\3`, not `\2`. Implementations MUST count groups consistently with whatever alternation form they emit.

**Per-recipient ordering — what "per recipient" means.** The peer block presented to recipient R contains every other reviewer's prior-round output (per terminal-abstention rule, including abstained peers as `(peer abstained)`). The ORDER of those entries differs per recipient: claude's peer block may show `Peer-B, Peer-A`; codex's peer block may show `Peer-A, Peer-B`; etc. Deterministic under `--debate-seed`, non-deterministic without.

**Wiring map** (anonymization output → next-round prompt):
- Reviewer Round-1 outputs (in staging) → deny-list scrub (iterative loop) → peer ordering (seeded or production) → rendered peer block (per skeleton) → exported `PEER_BLOCK_<recipient>` variable → bin/review-gate `${PEER_BLOCK}` substitution slot in reviewer prompt (T004) → Round-2 prompt (T008 launches)

**Bash 3.2.** No associative arrays; use parallel arrays keyed by canonical reviewer name. The do-while loop form is unambiguously portable across BSD and GNU sed.
